# Mandala Generator — версия для Windows

Сборка и распространение программы Mandala в виде исполнимого файла
`.exe` (и/или установщика) для Windows. Документ охватывает два сценария:
**сборку** (у вас есть Python на Windows) и **использование** (просто
запуск готового exe/установщика).

Базовый проект и исходники: <https://github.com/zah108/Mandala> —
полная документация программы в `README.md` / `README_RU.md`.

---

## 1. Состав папки `mandala39-WindowsBuild`

| Файл / папка | Назначение |
| --- | --- |
| `mandala/` | Копия пакета программы (из `mandala-39-Github`), с мелкими адаптациями под exe (см. раздел 5) |
| `run_mandala.py` | Точка входа для exe: находит cairo-DLL, задаёт рабочую папку, вызывает `mandala.main.main()` |
| `build_exe.spec` | Спека PyInstaller (onedir, окно без консоли) |
| `build_exe.bat` | Скрипт сборки одним запуском: зависимости + PyInstaller + DLL cairo |
| `requirements.txt` | Зависимости сборки: `pyinstaller`, `cairocffi`, `pillow` |
| `config_override_example.py` | Образец пользовательских параметров (для переименования в `mandala_config_override.py`) |
| `MandalaInstaller.iss` | Скрипт Inno Setup для сборки установщика Windows |
| `README_Windows.md` | Этот документ |

Не попадает в репозиторий: `build/`, `dist/`, `INSTALLER/`, `cairo_dll/`,
`__pycache__/` (см. `.gitignore`).

## 2. Сборка exe (на компьютере с Windows)

### Предпосылки

1. **Python 3.9+** для Windows (<https://www.python.org/downloads/>) —
   при установке отметить **«Add python.exe to PATH»**.
2. **GTK-3 Runtime** (только на машине сборки, конечным пользователям
   не понадобится — DLL кладутся в комплект):
   <https://github.com/tschoonj/GTK-for-Windows-Runtime-Environment-Installer/releases>
   — при установке отметить галочку *Set up PATH*. Даёт нужную
   `libcairo-2.dll` (это единственная нативная зависимость cairocffi,
   из pip она не приходит).

### Сборка

1. Открыть папку `mandala39-WindowsBuild` в проводнике.
2. Дважды запустить **`build_exe.bat`** (или из терминала: `build_exe.bat`).
3. Дождаться сообщения **ГОТОВО**. Результат:

   ```
   dist\
   └── MandalaGenerator\
       ├── MandalaGenerator.exe      ← запускаемая программа
       ├── config_override_example.py
       ├── cairo_dll\                ← DLL Cairo в комплекте
       └── _internal\                ← служебные данные Python/Rt
   ```

4. Первый тест: двойной щелчок по `MandalaGenerator.exe` — окно мандалы
   должно открыться и дорисоваться, картинка пишется в `dist\...\img`,
   лог в `dist\...\log`.

### Почему `onedir`, а не `onefile`

- Вариант «один exe» звучит удобнее, но у onefile каждую свою работу
  распаковывает во временный каталог: медленный старт, антивирусы
  недолюбливают, и служебные `img/`/`log/` оказываются не рядом
  с программой. `onedir` стартует быстро и полностью самодостаточен:
  папку целиком копируют/архивируют/устанавливают.
- Для раздачи довольно `ZIP` папки `dist\MandalaGenerator`.
- Для установки «как у взрослых программ» — см. раздел 4 (Inno Setup).

## 3. Параметры рисования в готовом exe

Все параметры заданы в `mandala/config.py` (см. подробное описание
в основном `README_RU.md`, раздел про `Config`). В **exe** сами
исходы вшиты внутрь, поэтому параметрами управляет переопределяющий
файл:

1. Переименуйте `config_override_example.py` → **
   `mandala_config_override.py`** и положите **рядом
   с `MandalaGenerator.exe`** (в ту же папку).
2. Откройте его в «Блокноте» и раскомментируйте/задайте нужные
   параметры (все имена — как в `config.py`, значения — только что
   было приведено в образце):

   ```python
   DRAW_SPEED_LEVEL = 12
   SAVE_FORMAT = "png"
   CIRCLE_RADIUS = 470
   ```

3. Сохраните файл и запустите exe как обычно. Факт применения
   переопределений фиксируется в логе:

   ```
   Config: применены переопределения из ...\mandala_config_override.py (3 параметров)
   ```

Из исходников переименовывать образец следует в `config_override.py`
и класть внутрь папки `mandala/` — этот же механизм действует и там.

Правило именования обязательное: только **ВЕРХНИЙ регистр** имён,
которые совпадают с параметрами `config.py` (приватные поля класса,
`_speed_level` и т. п., переопределять не нужно).

## 4. Установщик (optional / доп. сценарий)

После сборки exe можно завернуть папку в классический установщик
«далее‑далее‑готово»:

1. Установить **Inno Setup 6**: <https://jrsoftware.org/isdl.php>.
2. Открыть `MandalaInstaller.iss` в Inno Setup Compiler.
3. **Build → Compile** — результат в `INSTALLER\MandalaSetup.exe`.

Что делает установщик: кладёт всю программу в
`C:\Program Files\Mandala Generator` (или в профиль пользователя —
PrivilegesRequired=lowest), создаёт значки (рабочий стол + группа
«Пуск»), может сразу запустить первый запуск — и приносит
деинсталлятор, включая удаление `img/` и `log/`.

Готовый `MandalaSetup.exe` (несколько десятков MБ) — главный файл
раздачи для пользователей Windows.

## 5. Что изменено в коде пакета для exe (и почему)

Три маленькие правки, каждая помечена комментарием
`Windows build (PyInstaller) adaptation`:

| Модуль | Что правилось | Зачем |
| --- | --- | --- |
| `export.py` | Каталог экспорта `img/` **теперь рядом с exe** (dirname `sys.executable`), а не внутри `_internal` | Иначе картинки утекали во внутреннюю служебную папку сборки |
| `logging_utils.py` | Тот же перенос `log/` рядом с exe | То же для лога |
| `config.py` | В конце файла — загрузчик переопределений (`config_override.py` / `mandala_config_override.py`) | Чтобы «вшитый» в exe Config можно было настраивать без пересборки |
| (вне пакета) `run_mandala.py` | Добавляет папку `cairo_dll` к PATH и DLL-директориям | Доставляет libcairo до импорта cairocffi |

В исходной версии (репозиторий) эти правки не требуются — при запуске
из исходников ничего не меняется. При желании правки можно включить
и в основную историю (они безопасны: в обычном запуске `frozen`-ветка
не срабатывает).

## 6. Раздача пользователям (шпаргалка)

| Способ | Файл | Действие получателя |
| --- | --- | --- |
| ZIP | `MandalaGenerator-Win64.zip` (архив `dist\MandalaGenerator`) | Распаковать → запустить `MandalaGenerator.exe` |
| Установщик | `MandalaSetup.exe` (Inno Setup) | Запустить → далее → готово |

Оба способа **не требуют** установки Python и GTK — всё в комплекте.

Раздаваться удобно через GitHub Releases: приложить к релизу
`MandalaGenerator-Win64.zip` и/или `MandalaSetup.exe`
(см. инструкцию публикации в PDF).

## 7. Отгаданные проблемы (troubleshooting)

| Симптом | Причина | Что делать |
| --- | --- | --- |
| Окно открылось, но при сохранении ошибка `OSError: cannot load library 'libcairo-2.dll'` | Сборка выполнена без DLL (пункт «Где взять DLL» пропущен, в `dist\...\cairo_dll` пусто) | Пересобрать на машине с GTK-3 Runtime (см. раздел 2) — или скопировать DLL вручную: `libcairo-2.dll` и сопутствующие |
| `python не найден` при запуске bat | Python без PATH | Переустановить Python с галочкой «Add python.exe to PATH» |
| exe открывается и мгновенно закрывается | Окно проглотило ошибку старта | Запустить из терминала `dist\MandalaGenerator\MandalaGenerator.exe` — ошибка будет напечатана |
| Антивирус ругается на exe | Ложные срабатывания PyInstaller | Добавить в исключения; для «большой» сборки см. документ PyInstaller |
| `Config: параметры не применились` | Файл не рядом с exe / имя без `.py` / параметр не в ВЕРХНЕМ регистре / неверный синтаксис | Проверить: имя точно `mandala_config_override.py`, код — валидный Python, параметры CAPS |
| Картинки не появились | Сгенерированное изображение пишется при подрезке пера | Смотреть лог: он в `log\YYYY-MM-mandala.log` рядом с exe |

## 8. Замечания и ограничения

- Сборку ведут **только на Windows** — PyInstaller не кросс-платформенный
  (на macOS exe собрать нельзя, и наоборот).
- Tkinter входит в состав Python для Windows — отдельной установки
  не требует и в exe входит PyInstaller'ом.
- `git`-репозиторий: папку сборки можно держать вне репозитория или
  закоммитить (в ней нет артефактов — только исходники, спека и
  документация; см. `.gitignore`).
