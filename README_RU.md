# Mandala Generator

Генератор мандал на Python + Cairo. Программа собирает
мандалу из независимых модулей — центрального узора, пяти
разделительных лент и пяти слоёв лепестков — случайно комбинируя
стили и цвета, рисует её в окне как анимацию, а затем сохраняет
результат в векторный PDF (или растровый PNG/JPG) и пишет
подробный лог в текстовый файл.

Код написан с использованием LLM (Large Language Model)

## Быстрый старт

Из корня проекта (там, где лежит папка `mandala/`):

```bash
python -m mandala
```

Флаг `-m` говорит Python: «найди указанный пакет/модуль и выполни его
как программу». Для `python -m mandala` Python ищет пакет `mandala`
в текущем каталоге (и в `PYTHONPATH`), запускает его `__main__.py`,
а тот вызывает `main()`. Именно поэтому команда выполняется из папки,
в которой лежит `mandala/`, — иначе Python пакет не найдёт.

или

```bash
python -m mandala.main
```

В окне мандала рисуется как анимация; после завершения в каталоге
`img/` создаётся файл `YYYY-MM-DD-mandala-HHMMSS.pdf`
(или `.png`/`.jpg`), а в каталоге `log/` — запись в
`YYYY-MM-mandala.log`.

Если вы работаете в VS Code и хотите запускать кнопкой **Run code**
на `mandala/main.py` — это тоже поддерживается (см. раздел
[Запуск из VS Code](#запуск-из-vs-code)).

## Структура проекта

```
mandala/
├── __init__.py          # маркер пакета (может быть пустым)
├── __main__.py          # позволяет `python -m mandala`
├── main.py              # оркестратор: связывает модули, запускает генерацию
├── config.py            # класс Config — все настроечные параметры
├── runtime.py           # Cairo-сцена, окно Tkinter, turtle-подобный API,
│                        # менеджер анимации, скорость, тайминги
├── traj.py              # элементы траектории анимации: Line, Arc, Bezier,
│                        # FillElement (заливка), StrokeElement (обвод)
├── selection.py         # выбор цветов и стилей (взвешенный random + правила)
├── geometry.py          # общие утилиты рисования (окружности, полилинии, овалы)
├── centers.py           # 11 вариантов центра + SVG-парсер для символа Ом
├── bands.py             # 12 стилей разделительных лент
├── layers.py            # 17 стилей слоёв лепестков
├── logging_utils.py     # формирование и запись лога
└── export.py            # сохранение сцены: векторный PDF через Cairo,
                         # растр PNG/JPG через PIL
```

Во время работы создаются рабочие каталоги (в каталоге проекта):

```
img/                     # результаты: PDF/PNG/JPG
log/                     # текстовые логи по месяцам
```

### Назначение модулей

| Модуль | Функционал |
| --- | --- |
| `config.py` | Только данные: цвета фона/линий, радиусы, ширины, палитры, каталоги стилей, режимы. **Ничего не импортирует** — это лист дерева зависимостей. |
| `traj.py` | Элементы анимации с собственной длиной: `Line`, `Arc`, `Bezier` (параметризация по длине дуги через LUT), `FillElement` (заливка, нулевая длина), `StrokeElement` (обвод готового контура). |
| `runtime.py` | Окно Tkinter + Cairo-сцена, turtle-подобный API (`goto`, `penup`, `pendown`, `begin_fill`, `circle` и т.д.), слияние дуг заливки в круговые контуры, менеджер анимации (`AnimationManager`), слой «выпечки» (`_bake`), тайминги фаз. |
| `selection.py` | Состояние палитры (`COLOR_ENABLED`, `ACTIVE_PALETTE`), функции `pick_color_no_adjacent`, `pick_colors_for`, `pick_styles_with_rules`, `weighted_choice_styles`, а также счётчики `colors_count_for_*`. |
| `geometry.py` | `draw_circle_from_center`, `fill_ring`, `petal_points`, `draw_polyline`, `draw_oriented_oval`, `shape_leaf`, `draw_small_circle`. |
| `centers.py` | Функции `center_v1..center_v11` + диспетчер `draw(style_idx, r, colors)`. Внутри — SVG-парсер для Ом. |
| `bands.py` | `generic_band()` + `band1_run..band5_run` + диспетчер `draw_band(index, r, w, colors)`. |
| `layers.py` | `draw_layer_core()` + `layer1_run..layer5_run` + диспетчер `draw_layer(index, r, ring, petal_colors)`. |
| `logging_utils.py` | `build_start_log`, `write_start_log`, `build_end_log`, `write_end_log`, `setup_log_path`. |
| `export.py` | `save_mandala(scene, mandala_name)` — сцена пишется напрямую в PDF (`cairo.PDFSurface`) или растеризуется в PNG/JPG через PIL. |
| `main.py` | Собирает всё вместе: выбирает стили и цвета, вызывает отрисовку, сохраняет результат. Плюс «хак» для запуска напрямую (`Run code`). |

### Граф зависимостей

```
config  ←  runtime  ←  geometry  ←  centers
                       ↑            ←  bands
                       ↑            ←  layers
config  ←  selection
config  ←  logging_utils
config  ←  export  ←  runtime
main    →  всё вышеперечисленное
```

`config.py` не импортирует ничего из проекта. `runtime.py` зависит
только от `config` (и внешних библиотек). `selection.py` — только
от `config`. Всё остальное собирается в `main.py`.

## Как это работает

### Общая идея

Мандала — это **набор концентрических областей**. Области двух типов:

- **Центр** — круг радиуса `CIRCLE_RADIUS`.
- **Разделительные ленты** (bands) — узкие кольца между слоями.
- **Слои лепестков** (layers) — широкие кольца с орнаментом из
  повторяющихся лепестков.

Области идут строго в порядке:

```
центр
  лента 1   (BAND1_WIDTH)
  слой 1    (L1_WIDTH)
  лента 2   (BAND2_WIDTH)
  слой 2    (L2_WIDTH)
  лента 3   (BAND3_WIDTH)
  слой 3    (L3_WIDTH)
  лента 4   (BAND4_WIDTH)
  слой 4    (L4_WIDTH)
  лента 5   (BAND5_WIDTH)
  слой 5    (L5_WIDTH)
```

Радиусы вычисляются в `main._compute_radii()` простым
накоплением:

```python
r_band1_start = CIRCLE_RADIUS
r_layer1_start = r_band1_start + BAND1_WIDTH
r_band2_start = r_layer1_start + L1_WIDTH
...
```

### Порядок работы `main.main()`

1. **`runtime.apply_draw_speed(DRAW_SPEED_LEVEL)`** — фиксирует
   целевую длительность рисования (см. раздел
   [Анимация и скорость отрисовки](#анимация-и-скорость-отрисовки)).

2. **`selection.init()`** — определяет `COLOR_ENABLED`
   (`"yes"`/`"no"`/`"random"`), выбирает семейство палитры
   (`PALETTE_CHOICE`), заполняет `ACTIVE_PALETTE`.

3. **Выбор стилей** — `weighted_choice_styles` для центра,
   `pick_styles_with_rules` (с `max_repeat=1`, т.е. без повторов)
   для 5 лент и 5 слоёв.

4. **Выбор цветов** (`_pick_all_colors`) — по областям сверху вниз,
   с учётом запретов на повторы (см. ниже).

5. **Запись лога старта** — какие стили и цвета выбраны.

6. **Отрисовка** — по очереди: `centers.draw`, `bands.draw_band`,
   `layers.draw_layer` для каждой области. Каждый вызов обёрнут
   `_tmark(...)` для таймингов. Операции записываются в векторную
   сцену Cairo (`Scene`) и в траекторию `AnimationManager`.

7. **Анимация** — `runtime.done(lambda: ...)`: окно показывает
   рисование «живьём» (см. раздел ниже); цикл блока mainloop —
   `after(16)` ≈ 60 кадров/с.

8. **Сохранение** — после завершения анимации
   `export.save_mandala(scene, mandala_name)`: векторная сцена
   пишется напрямую в PDF через `cairo.PDFSurface` или растеризуется
   в PNG/JPG через PIL.

9. **Запись лога конца** — статус сохранения и тайминги.

### Как рисуется лепесток

Почти все стили лепестков строятся через `geometry.petal_points`:

```python
def petal_points(inner_r, outer_r, phi, half_angle, shape_fn, steps=8):
    # левая сторона лепестка: phi - half_angle*shape_fn(t),
    # правая: phi + half_angle*shape_fn(t)
    # на каждом радиусе r = inner_r + (outer_r - inner_r) * t
```

`phi` — угол лепестка, `half_angle` — половина шага между
лепестками (`2π / num_petals / 2`), `shape_fn(t)` — форма лепестка
(например, `sin(π t)` даёт классический лист). Обход даёт замкнутый
контур (закрытый по дуге внутреннего радиуса), который Cairo
заливает цветом; база лепестков лежит строго на окружности границы.

### Как рисуется лента

`bands.generic_band` — большой `if/elif` по `style_type` (1..12).
Для каждого `style_type` своя логика: прямые штрихи, кружки,
зигзаги, ромбы, волны и т.д. Количество элементов в ленте
подбирается так, чтобы кружки/ромбы не наезжали друг на друга.

### Особый случай: Ом

`centers.center_v7` рисует символ Ом из SVG-путей
(`centers.OM_SVG_PATHS`). Парсер (`_parse_svg_path`) понимает
только подмножество SVG-команд: `M/m`, `L/l`, `C/c`, `Z/z`.
Кривые Безье аппроксимируются 12 отрезками. Результат
нормализуется и масштабируется под радиус центра.

## Анимация и скорость отрисовки

### Как устроена анимация

- Все операции рисования записываются в **траекторию**
  (`AnimationManager.trajectory`): отрезки и дуги несут свою длину,
  заливки (`FillElement`) имеют нулевую длину и «выполняются
  мгновенно», когда перо доходит до их точки.
- Прогресс вычисляется от общего пройденного пути
  (`elapsed × speed_px_s`), поэтому перо движется с постоянной
  скоростью независимо от типа элементов.
- Каждый кадр: завершённые элементы один раз «выпекаются» на
  накопительный слой (`_bake`), поверх добавляется только текущий
  частичный элемент — постоянная стоимость кадра.
- Таймер анимации стартует с момента открытия окна (а не с начала
  построения сцены); цикл — `after(16)` ≈ 60 кадров/с
  (`SPEED_FPS`).

### Шкала скорости

Скорость отрисовки контролируется параметром `DRAW_SPEED_LEVEL`
(целое от 1 до 20). Уровень задаёт **длительность рисования**
(линейная шкала с постоянным шагом ≈23 с):

- **1** — самая медленная (~7 мин 20 с = 440 с)
- **10** — средняя (~3 мин 54 с, по умолчанию)
- **20** — максимальная (~4 с)

`SPEED_DURATION_MAX_S` / `SPEED_DURATION_MIN_S` — границы шкалы.
Реальная скорость (px/с) вычисляется из фактической длины
траектории перед стартом анимации, поэтому длительность не зависит
от конкретного узора. Геометрия и цвет от уровня не зависят —
меняется только темп показа.

Изменять их можно прямо в файле.

| `BAND2_WIDTH` | `14` | Ширина разделительной ленты 2 |

| 15 | Двойной полулист (с точкой) | Два вложенных контура + точка между ними |
| 16 | Тройной ромб с пестиком | Ромб + точка + отрезок к центру |
| 17 | Двойной лист с точкой | Лепесток + уменьшенный лепесток внутри + точка |

### Как выбираются стили

```python
style_center = selection.weighted_choice_styles(
    list(Config.CENTER_STYLES.keys()), Config.CENTER_STYLES)

band_styles  = selection.pick_styles_with_rules(5, Config.BAND_STYLES,  max_repeat=1)
layer_styles = selection.pick_styles_with_rules(5, Config.LAYER_STYLES, max_repeat=1)
```

- `weighted_choice_styles` — один выбор по весам.
- `pick_styles_with_rules(n, dict, max_repeat=k)` — `n` слотов,
  каждый стиль не повторяется чаще `k` раз и не идёт подряд
  дважды. При `max_repeat=1` — все 5 лент и все 5 слоёв
  **различны**.

Результаты передаются в `bands.set_styles(...)` и
`layers.set_styles(...)` — это единственная «глобальная» настройка
в этих модулях.

## Палитры цветов

Определены в `Config.COLOR_FAMILIES`. Четыре семейства:

| Семейство | Комментарий | Примеры цветов |
| --- | --- | --- |
| `warm_soft` | Тёплые пастельные | `#e8a87c`, `#f0d8a8`, `#e3c4a8` |
| `cool_soft` | Холодные пастельные | `#a8c5a0`, `#8fbcd4`, `#b8a4c9` |
| `warm_bright` | Тёплые яркие | `#f4a261`, `#e76f51`, `#bc4749` |
| `cool_bright` | Холодные яркие | `#2a9d8f`, `#3d6a99`, `#7f63a8` |

В каждом семействе по 11 цветов, каждый — словарь
`{"hex": "#rrggbb", "weight": 1.0}`. Вес влияет на вероятность
выбора.

### Параметр `PALETTE_CHOICE`

| Значение | Поведение |
| --- | --- |
| `"random"` | При каждом запуске случайно выбирается одно из 4 семейств |
| `"all"` | Все 4 семейства объединяются в один пул (44 цвета), выбор идёт из него |
| `"warm_soft"` | Только тёплые мягкие |
| `"cool_soft"` | Только холодные мягкие |
| `"warm_bright"` | Только тёплые яркие |
| `"cool_bright"` | Только холодные яркие |
| любое другое | Ведёт себя как `"random"` |

### Параметр `COLOR_MODE`

| Значение | Поведение |
| --- | --- |
| `"yes"` | Раскраска всегда включена |
| `"no"` | Раскраска всегда выключена |
| `"random"` | При каждом запуске случайно: включена или выключена |

Если раскраска выключена (`COLOR_ENABLED = False`), рисуются только
контуры цветом `LINE_COLOR`, без заливок.

## Выбор цветов: правила и запреты

Каждая область (центр, лента, слой) запрашивает у `selection`
определённое количество цветов:

| Область | Сколько цветов |
| --- | --- |
| Центр, стиль 2 или 9 | 2 (кольцо + внутренний) |
| Центр, остальные | 1 |
| Лента, стиль 4 | 3 (фон, внешний, внутренний) |
| Лента, стиль 2, 6, 9 | 2 (фон, элемент) |
| Лента, остальные | 1 |
| Слой, стиль 2 | 2 (внешний овал, внутренний овал) |
| Слой, стили 3, 7, 9, 11, 14, 15 | 3 |
| Слой, остальные | 2 |

### Функция `pick_colors_for(n, forbidden_hard, forbidden_soft, area_label)`

Выбирает `n` цветов, каждый раз проверяя три уровня запретов:

1. **`forbidden_hard`** — цвета, которые нельзя брать ни при каких
   условиях (например, цвет предыдущей области целиком).
2. **`forbidden_soft`** — цвета, которые нежелательно брать (цвет
   позапрошлой области).
3. **`recent_colors`** — два последних выбранных цвета (защита от
   «полосатого» повтора внутри одной области).

Если все цвета запрещены, запреты ослабляются по цепочке:

```
сначала снимается soft → затем hard → затем recent
```

Каждое ослабление фиксируется в `_fallback_warnings` и попадает в
лог. Пример предупреждения:

```
область 'слой 3': ослаблен запрет на предыдущую область
```

Это значит, что при выборе цвета для слоя 3 пришлось взять цвет,
который уже был в предыдущей области — иначе выбора не осталось.

### Продвижение истории

После каждой области вызывается:

```python
selection.advance_history(colors_used_in_area)
```

Она сдвигает `prev2_colors = prev_colors`, `prev_colors = новые`.
Таким образом «соседние области» не повторяют цвет друг друга, а
«через одну» — тоже стараются не повторять (soft-запрет).

## Сохранение результата

Рисование идёт на **Cairo**: сцена хранит векторные операции (штрихи и
заливки) и рисуется двумя способами:

1. **в окне** — анимация (`AnimationManager` + слой `_bake`):
   линии гладкие, заливки появляются в момент прохода пера;
2. **в файл** — та же сцена пишется прямо в PDF (вектор) через
   `cairo.PDFSurface` или растеризуется в PNG/JPG через PIL.

`SAVE_FORMAT`:

- `"pdf"` — векторный PDF в `img/`;
- `"png"` / `"jpg"` — растровая картинка (для быстрого просмотра).

Имя файла: `YYYY-MM-DD-mandala-HHMMSS.<ext>`. Файл создаётся только
после полного завершения анимации.

## Запуск из VS Code

### Способ 1 — из терминала

Откройте терминал в корне проекта (там, где папка `mandala/`) и
выполните:

```bash
python -m mandala
```

### Способ 2 — кнопка Run code

В `mandala/main.py` в самом начале есть блок:

```python
if __name__ == "__main__" and __package__ in (None, ""):
    ...
    rc = subprocess.run(
        [sys.executable, "-u", "-m", f"{_pkg_name}.main"],
        env=env, cwd=os.getcwd()
    ).returncode
    sys.exit(rc)
```

Он срабатывает, когда `main.py` запущен **напрямую** (как скрипт, а
не как модуль пакета). Блок:

1. Добавляет родителя пакета в `PYTHONPATH`.
2. Ставит `PYTHONUNBUFFERED=1` и передаёт `-u` — чтобы вывод
   дочернего процесса не буферизовался.
3. Запускает `python -m mandala.main` через `subprocess.run`,
   **наследуя stdio** — весь вывод идёт в ту же консоль, где был
   запущен `main.py`.

Благодаря этому кнопка **Run code** на `mandala/main.py` работает и
`print(...)` виден в Output/терминале.

> ⚠️ Не заменяйте `subprocess.run` на `os.execv` — `execv` подменяет
> процесс, и Code Runner теряет связь с его stdout/stderr: программа
> работает, но вывод в консоль пропадает.

### Способ 3 — `tasks.json` / `launch.json`

Создайте `.vscode/tasks.json`:

```json
{
    "version": "2.0.0",
    "tasks": [{
        "label": "Run mandala",
        "type": "shell",
        "command": "python",
        "args": ["-m", "mandala"],
        "options": { "cwd": "${workspaceFolder}" },
        "group": { "kind": "build", "isDefault": true },
        "problemMatcher": []
    }]
}
```

И `.vscode/launch.json` для отладки:

```json
{
    "version": "0.2.0",
    "configurations": [{
        "name": "Python: mandala (module)",
        "type": "debugpy",
        "request": "launch",
        "module": "mandala",
        "cwd": "${workspaceFolder}",
        "console": "integratedTerminal",
        "justMyCode": false
    }]
}
```

После этого: **Ctrl+Shift+B** — запуск задачи, **F5** — запуск в
дебаггере.

### Положение окна на экране

Окно создаётся с дефолтной геометрией Tkinter (по центру — в
зависимости от оконного менеджера). Его положение можно задать
стандартным способом Tkinter — вызовом
`self.root.geometry("1000x1000+X+Y")` в `Screen.__init__`
(`runtime.py`), где X/Y — координаты левого верхнего угла в
пикселях.

## Требования

- **Python 3.9+** (используются стандартные `math`, `re`, `random`,
  `datetime`, `subprocess`, `tkinter`).

- **Cairo** (`pip install cairocffi`) — рисует и окно, и PDF.
  На macOS библиотеку `libcairo` ставит Homebrew (`brew install cairo`);
  модуль сам добавляет `/opt/homebrew/lib` в путь поиска.
- **Pillow** (`pip install pillow`) — показ кадра в окне и экспорт `png/jpg`.
- **Tkinter** — входит в стандартную поставку Python (в некоторых
  Linux-дистрибутивах ставится отдельно: `sudo apt install python3-tk`).

## Частые вопросы

### Почему мандала получилась без цветов?

Проверьте `Config.COLOR_MODE` — если `"no"` или `"random"` (и
выпало выключение), раскраска не применяется. Также проверьте, что
`PALETTE_CHOICE` указывает на существующее семейство (или `"all"` /
`"random"`).

### Почему в логе появились «Предупреждения раскраски (fallback)»?

Это не ошибка. Это значит, что для какой-то области не осталось
цветов после применения всех запретов, и пришлось ослабить один из
запретов (см. раздел
[Выбор цветов: правила и запреты](#выбор-цветов-правила-и-запреты)).
Если предупреждений слишком много — уменьшите палитру
(`PALETTE_CHOICE = "warm_soft"` и т.п.) или добавьте цветов в
`COLOR_FAMILIES`.

### Возникла ошибка при сохранении PDF

Ghostscript не требуется — программа сохраняет PDF напрямую через
Cairo. Убедитесь, что установлен `cairocffi`
(`pip install cairocffi`) и библиотека `libcairo`
(на macOS: `brew install cairo`). Либо переключите
`SAVE_FORMAT = "png"` или `"jpg"` — тогда используется только PIL.

### Почему кнопка Run code в VS Code ничего не выводит в консоль?

Скорее всего, вы заменили `subprocess.run` на `os.execv` — `execv`
подменяет процесс, и Code Runner теряет stdout. Верните
`subprocess.run` (см. раздел
[Запуск из VS Code](#запуск-из-vs-code)).

### Как задать положение окна на экране?

Вызовите `self.root.geometry("1000x1000+X+Y")` в `Screen.__init__`
(`runtime.py`) — см. раздел
[Положение окна на экране](#положение-окна-на-экране).

### Как сделать мандалу крупнее/мельче?

Увеличьте/уменьшите `CIRCLE_RADIUS`, `BAND*_WIDTH` и `L*_WIDTH` в
`Config`. Внешний радиус = сумма всех ширин + `CIRCLE_RADIUS`.
Не забудьте, что `WINDOW_SIZE` должен быть больше внешнего радиуса
мандалы, иначе рисунок обрежется окном (и PDF-страницей).

### Как отключить тайминги?

`Config.TIMING_ENABLED = False` (по умолчанию и так `False`). Тогда
`_tmark`/`_timing_report` ничего не пишут.

### Как запустить без окна (headless)?

Программа рассчитана на визуальное окно Tkinter. В headless-
окружении (сервер без дисплея) создание окна упадёт с
`TclError` ещё до отрисовки. Для CI/серверов нужен виртуальный
дисплей (`xvfb-run python -m mandala`).
